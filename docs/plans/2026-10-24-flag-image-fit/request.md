# 実装依頼: 国旗サムネイルの白い隙間をなくす（比率が近い旗だけ cover 表示）

## 背景

返信のボタンテンプレートでは国旗を `imageAspectRatio: rectangle`（1.51:1 の枠）、`imageSize: contain`、背景白で表示している。3:2（1.5:1）など枠とほぼ同じ比率の旗でも横がわずかに足りず、実機で左右に 1〜2px の白い筋が見える。196 枚のうち 87 枚が 1.5:1 で、最も多いケースでこの筋が出ている。

この変更により、比率が枠に近い旗は `imageSize: cover` で枠いっぱいに表示し、白い筋をなくす。切れるのは端の 10% 以内に抑える。イギリス（2:1）、スイス（1:1）、ネパール（縦長）のように比率が大きく違う旗は従来どおり contain で全体を表示する。contain のまま残る旗は、どれも上下または左右に各 5.6% 以上のはっきりした余白になり、数 px の細い白い筋は出ない。

cover / contain の判定に必要な旗の寸法は、ツール実行時に PNG から読み取って Go のソースとして生成・commit する。Workers 実行時に PNG を読んだり追加の JSON を解析したりはしない。

### 判定の基準

LINE の rectangle 枠は 1.51:1。旗の比率 r（幅/高さ）を枠に cover で入れたとき切れる割合を次のように定める。

- r ≥ 1.51 のとき: 幅の `1 - 1.51 / r`
- r < 1.51 のとき: 高さの `1 - r / 1.51`

この割合が **10% 以下**の旗を cover、それ以外を contain にする。閾値は包含（ちょうど 10% は cover）。この基準で現在の 196 枚のうち 122 枚が cover になり、最大で幅の約 9.4% が切れる（5:3 の旗など）。contain のまま残るのは 74 枚（比率 0.82、1.00、1.16、1.17、1.25、1.33、1.70、1.75、1.77、1.82、1.90、2.00、2.54）で、余白は片側 5.6% 以上になる。閾値は `internal/country` の定数 1 か所で変更できるようにする。

例の国: JP（1.50）・BR（1.43）・AR・DE（5:3）・NO は cover（`FlagFitsFrame()` が true）。GB（2:1）・CH（1:1）・NP（縦長）・US・CV・MX・SM は contain（false）。

### 整数演算の判定式

判定関数 `fitsFrame(w, h int) bool` は整数演算で行い、浮動小数を使わない。幅 w、高さ h、枠 151:100、閾値 10% のとき:

- w×100 ≥ h×151（旗が枠より横長または同じ）なら `151×h×100 ≥ 90×100×w` で cover
- それ以外なら `100×w×100 ≥ 90×151×h` で cover
- w または h が 0 以下、または寸法が未登録のコードは contain（安全側）

### データの持ち方

- 旗の寸法は `tools/fetchflags` が PNG のヘッダ（`image/png` の `DecodeConfig`。画像本体は復号しない）から読み取り、`internal/country/flagsizes_gen.go` に Go の map リテラルとして書き出す。先頭行は `// Code generated by tools/fetchflags; DO NOT EDIT.`。コード順にソートし、`gofmt` 済みの出力にする。
- 生成ファイルの内容（概形）:

```go
// Code generated by tools/fetchflags; DO NOT EDIT.

package country

// flagSizes is the pixel size of public/flags/{code}.png, keyed by ISO code.
var flagSizes = map[string]flagSize{
	"AD": {W: 320, H: 224},
	...
}
```

- `flagSize` 型、枠の定数、閾値、判定関数は手書きの `internal/country/flag.go` に置く。
- `Country` に `FlagFitsFrame() bool` を追加する。`internal/country` は `internal/line` に依存しないため、bool を返し、`internal/bot` 側で `line.ImageSizeCover` / `line.ImageSizeContain` に変換する。
- `countries.json` は変更しない。寸法は旗画像から派生する情報であり、Wikidata 由来のデータと生成元が異なるため、別ファイルにする。
- 実行時コスト: 生成ファイルは 196 要素の map リテラルで、起動時の初期化は無視できる。1 返信あたりの追加処理は整数の乗算と比較が数回。wasm サイズの増加は数 KB 程度の見込みで、`scripts/check-size.sh` で確認する。

### 生成ツールの契約

- `go run ./tools/fetchflags` をリポジトリ直下で実行すると、従来の取得・検査に続けて寸法ファイルを書き出す。出力先は `-sizes` フラグ（既定 `internal/country/flagsizes_gen.go`、空文字で生成を省略）。
- 全旗が揃っていれば取得はすべてスキップされ、ネットワーク不要で再生成できる。
- 寸法を読めない PNG があれば、そのコードを列挙して非 0 で終了する。
- 出力先が存在しないディレクトリならエラーで止める。

### 選ばなかった案（採用しない）

- cover にするコードの一覧（bool）だけを生成する案: 閾値変更のたびに再生成が必要で、閾値の境界をテストしづらい。
- 寸法を `countries.json` に追加する案: `tools/gencountries` が再生成すると消え、countries.json の形式を変えない方針とも合わない。
- 寸法を別 JSON として embed し実行時に解析する案: 実行時の解析コストを増やす。

次をすべて満たす証拠だけが検収で再利用される:

- 証拠のコマンド・cwd・範囲が必要な検証と一致している
- 検証コマンドとログ保存の両方の終了コードが 0
- 出力が途中で欠けていない
- 実行前後の HEAD が対象 HEAD と一致している
- tracked と index の差分が実行前後とも空

未 commit の内容を含めて実行した記録は再利用されないので、全件検証は commit 後に行う。履歴整理で HEAD だけが変わった場合は、tree が一致すれば同じ内容として扱われる。

### 保存できない場合

証拠ディレクトリに書き込めないときは、その旨と実行したコマンドを報告する。采配役が同じ worktree で同じコマンドを実行・記録して独立に検証する。生ログをリポジトリへ保存したり、権限を広げたりして解消しない。

### 返答に含めるもの

- 変更ファイル
- commit 一覧
- 証拠ディレクトリの場所
- 動作確認: `node scripts/local-smoke.mjs` による wrangler dev の 7 シナリオそれぞれのステータスと、返信 API のモックが受けた JSON の要点（日本の詳細が `"imageSize":"cover"`、イギリスの詳細が `"imageSize":"contain"` か）、`/flags/jp.png` の結果
- 生成データの件数と検証結果（`flagsizes_gen.go` のエントリ数、`FlagFitsFrame()` の true / false の枚数、`go run ./tools/fetchflags` 再実行時の差分の有無、`countries.json` の差分の有無）
- `scripts/check-size.sh` が示す wasm の gzip サイズ
- 判断に迷った点・未解決事項（既存テストを変更した場合はその理由を含む）

取得できた使用量だけを采配役へ返し、不明な値を推定しない。
未完了・失敗・未検証は区別する。
