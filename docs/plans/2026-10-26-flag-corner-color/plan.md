## 背景・目的

国名の返信とクイズは、国旗を buttons template の rectangle（1.51:1）枠に表示している。枠の比率に近い国旗（196 か国中 122 か国）は `imageSize: cover`、遠い国旗は `contain` で、背景色 `imageBackgroundColor` はどちらも `#FFFFFF` 固定である。

LINE はメッセージの上側の角を丸く切り抜く。cover の国旗では、画像の下に敷かれた白い背景が丸い角の縁のアンチエイリアスに混ざり、角の縁に 1px ほどの白い線が出る（ダークモードで目立つ。直線の辺には出ない）。

この変更で、国旗の取り込みツール `tools/fetchflags` が各国旗の「枠に表示したときの上の左右の角」の色を記録して生成コードに出し、cover の国旗はその色を背景色にする。左右の角の色が違う国は 2 色の中間色にする。contain の国旗は余白が白で本文の白とつながるため、白のままにする。国名の返信とクイズの両方に効かせる。

## 方針

### 角の色の決め方（tools/fetchflags）

1. **切り取りを考慮した位置を使う。** cover では枠より横長の国旗は左右が、縦長の国旗は上下が中央寄せで切り取られると仮定する（CSS の `background-size: cover; background-position: center` 相当）。切り取り量は `internal/country` の枠定数から求め、ツール側に比率を重複して持たない。

   `internal/country/flag.go` に次を追加する:

   ```go
   // FrameCrop returns how many pixels a w x h image loses on each side
   // (left and right, or top and bottom) when it fills the frame ("cover")
   // centred. Exactly one of dx, dy is non-zero unless the image has the
   // frame's shape. Invalid sizes return 0, 0.
   func FrameCrop(w, h int) (dx, dy int)
   ```

   横長（`w*frameH >= h*frameW`）なら `shownW = h*frameW/frameH`、`dx = (w-shownW)/2`、`dy = 0`。縦長なら `shownH = w*frameH/frameW`、`dy = (h-shownH)/2`、`dx = 0`。整数の切り捨て誤差（±1px）は次の内側オフセットで吸収する。

2. **端から少し内側の小領域の平均を取る。** 端 1 画素は縁取りやアンチエイリアスで混ざることがあるため、表示上の角から `cornerInset = 2` 画素内側を中心にした `cornerWindow = 3`（3×3 画素）の平均色を使う。表示上の左上の角は PNG の `(dx, dy)`、右上は `(w-1-dx, dy)` なので、左の標本中心は `(dx+2, dy+2)`、右は `(w-1-dx-2, dy+2)`。平均は成分ごとに `(sum + n/2) / n` で四捨五入する。定数は `tools/fetchflags` 側に置き、テストで値を固定する。

3. **左右が違えば中間色。** 左右の平均色が成分ごとにすべて一致しなければ、成分ごとに `(l + r + 1) / 2`（sRGB 値の算術平均、四捨五入）を取る。一致すればその色。

4. **全 196 か国を記録する。** cover か contain かはランタイムで判定するので、ツールは判定せず全国旗の角の色を書く。表の形が揃い、閾値の変更が生成物の再生成だけで済む。

5. **透過画素は白に重ねた色として扱う。** 標本領域の透明・半透明の画素（アルファが 255 未満）は、白（#FFFFFF）に重ねた色として平均に入れる。成分ごとに `c*a/255 + 255*(255-a)/255` を四捨五入する（`c` はアルファを掛けていない成分値。Go では `color.NRGBAModel` で変換した `color.NRGBA` の値を使い、アルファを掛けた値を返す `RGBA()` の戻り値は使わない）。contain の背景が白で、LINE は画像を背景に重ねて表示するため。`public/flags/` の 196 枚のうちアルファが 255 未満の画素を含むのは `np.png`（ネパール、320×390。四角くない旗）の 1 枚だけで、標本領域に透明な画素が入るが、ネパールは contain（背景は白）なので背景色の結果には影響しない。

6. **失敗条件。** PNG が復号できない、標本領域が画像からはみ出す（表示幅が `2*(cornerInset+1)+2` 未満、または表示高さが `cornerInset+2` 未満）のどちらかは、そのコードを失敗として一覧に出し、生成物を書かない（寸法の失敗と同じ扱い）。

### 生成物の形

- `internal/country/flagsizes_gen.go` を `internal/country/flags_gen.go` に改名し、1 つの表に寸法と角の色を持たせる。型名は `flagSize` → `flagInfo`、変数名は `flagSizes` → `flagInfos`。色は `uint32` の `0xRRGGBB`。

  ```go
  // Code generated by tools/fetchflags; DO NOT EDIT.

  package country

  // flagInfos is the pixel size of public/flags/{code}.png and the colour of
  // its top corners when shown in the image frame, keyed by ISO code.
  var flagInfos = map[string]flagInfo{
  	"AD": {W: 320, H: 224, Corner: 0x6E3368},
  	...
  }
  ```

- `uint32` にする理由: 文字列より wasm への寄与が小さく（196 × 4 バイト程度）、16 進リテラルは `#RRGGBB` と見た目が対応して読みやすい。文字列化は `fmt` を使わず、手書きの 16 進変換で行う（TinyGo のバイナリに `fmt` を持ち込まない）。
- ツール側の `-sizes` フラグは `-gen` に改名し、既定値を `internal/country/flags_gen.go` にする（空文字で生成を省く動きは維持）。

### internal/country の変更

```go
// flagInfo describes a flag image. flagInfos in flags_gen.go is generated by
// tools/fetchflags.
type flagInfo struct {
	W, H   int
	Corner uint32 // 0xRRGGBB at the top corners when shown in the frame
}

// FlagCornerColor returns the colour of the flag's top corners as shown in
// the image frame, "#RRGGBB". When the left and right corners differ it is
// the mean of the two. It is "" for a code without a known flag.
func (c *Country) FlagCornerColor() string

// hexColor formats 0xRRGGBB as "#RRGGBB" without fmt.
func hexColor(rgb uint32) string
```

- `FlagFitsFrame` は `flagInfos[c.Code]` を使うだけで振る舞いは変えない。
- `FlagCornerColor` は表に無いコードで `""` を返す（`FlagFitsFrame` も false なので、bot では contain・白になる）。

### internal/bot の変更

- `flagBackground` 定数を `flagBackgroundContain = "#FFFFFF"` に改名し、意味を contain の余白色に限定する。
- `flagImageSize(c)` を、表示方法と背景色を一緒に返す関数に置き換え、`detailMessage` と `quiz` の両方で使う。

  ```go
  // flagImage decides how a flag is shown. Flags close to the frame's shape
  // fill it ("cover") on a background of their own corner colour, so the
  // rounded corners do not show a light rim; other flags are shown whole on
  // white, which joins the white body below.
  func flagImage(c *country.Country) (size, background string) {
  	if c.FlagFitsFrame() {
  		if col := c.FlagCornerColor(); col != "" {
  			return line.ImageSizeCover, col
  		}
  		return line.ImageSizeCover, flagBackgroundContain
  	}
  	return line.ImageSizeContain, flagBackgroundContain
  }
  ```

- 契約・不変条件:
  - contain のときの背景色は常に `#FFFFFF`
  - cover のときの背景色は `c.FlagCornerColor()`（表に無ければ白だが、`FlagFitsFrame` が真なら必ず表にある）
  - 国名の返信（`detailMessage` で画像 URL があるとき）とクイズ（`quiz`）は同じ関数で決めるので食い違わない
  - 正解後の `detailMessage` は画像なし（従来どおり背景色を設定しない）

### 代替案と選ばなかった理由

- 別ファイル `flagcolors_gen.go` と別 map を足す: ルックアップと生成物が 2 つになり、片方だけ古くなる余地がある。1 つの表に統合する方が単純
- 色を文字列 `"#RRGGBB"` で生成する: 実行時の変換が不要だが wasm サイズへの寄与がやや大きく、`uint32` でも変換は数行で済む
- PNG の端の画素 `(1,1)` を使う: 切り取り後に表示されない位置を見ることがあり、縁取りやアンチエイリアスの混色を拾う。内側の小領域の平均の方が安定
- 寸法だけ `DecodeConfig` で読み、色は別に読む: 一度 `Decode` すれば両方取れる。196 枚の w320 PNG の復号はホストでは一瞬で、テストでも問題ない
- 左右の角で色が違う国に左右別の背景色を使う: LINE は 1 色しか指定できないため不可。利用者の決定どおり中間色にする
- 国旗の画像自体を加工する（角を丸めるなど）: 画像は Flagpedia のものをそのまま配信する方針と合わない

| 項目 | 内容 | 実装時の扱い |
|---|---|---|
| 生成ファイル名・型名 | 推奨: `flags_gen.go` / `flagInfo` / `flagInfos` に改名して 1 つの表に統合。代替: `flagsizes_gen.go` の名前を残して `Corner` を足す（名前と実態がずれる） | 推奨で進めてよい。改名の波及（テスト名、docs、`-gen` フラグ）を漏れなく直す |
| 色の保持形式 | 推奨: `uint32` の `0xRRGGBB` と `fmt` を使わない手書き変換。代替: 文字列 `"#RRGGBB"` | 推奨で進めてよい。TinyGo で文字列生成が問題を起こせば文字列形式に切り替えて報告 |
| 標本位置と窓 | 推奨: 表示上の角から 2px 内側を中心に 3×3 平均。代替: 端 1 画素、または 1px 内側の 1 画素 | 推奨で進める。生成結果で明らかに不自然な国（縁取りをまたいで混色するなど）があれば一覧にして報告し、定数の調整は止まって委ねる |
| 中間色の計算 | 利用者決定どおり sRGB 値の成分ごとの算術平均（四捨五入）。線形光での平均は採らない | 変更しない |
| 透過画素の扱い | 采配役が確定: 透明・半透明の画素は白（#FFFFFF）に重ねた色として平均に入れる（成分ごとに `c*a/255 + 255*(255-a)/255`、四捨五入）。理由: 196 枚のうち該当は contain のネパール（`np.png`）だけで、背景色の結果に影響しない | 変更しない。失敗にするのは PNG が復号できない場合と標本領域が画像からはみ出す場合だけ |
| cover の切り取りが中央寄せという仮定 | LINE の実装は非公開。中央寄せでなくても、ずれは最大 5%（w320 で 16px 以内）で、三色旗の帯（約 107px）内に収まる | 仮定で進める。実機確認で特定の国にだけ線が残れば、その国の旗の構造を確認して再検討 |
| tinygo-test の対象 | CI の tinygo-test ジョブは `tinygo test ./internal/...` で、`tools/fetchflags` は対象外（采配役が `.github/workflows/ci.yml` で確認済み）。`image/png` の完全復号はホストの Go だけで使う | 変更しない。`internal/country` と `internal/bot` の追加分は TinyGo のテストでも通す |
| `-sizes` フラグ名 | 推奨: `-gen` に改名（手元専用のツールで互換性は不要） | 推奨で進めてよい |
| local-smoke.mjs | 日本は角が白で期待値が変わらないため今回は触らない。フランスなど cover の有色の国を smoke に足すのは別作業 | 触らない。足す場合は別 PR |
| 片側が白の 8 か国 | bh, cl, cz, dj, mg, mt, pa, pk は片側の角が白で、中間色は白と色の中間になる。白側の角には従来より薄い線が残る可能性 | 利用者決定の範囲。報告のみ |
| 寸法だけの変化 | `public/flags` を差し替えると色も変わるので再生成が必要。既存の運用（再生成して commit）と同じ | 運用の変更なし |

## 公開経路

1. 実装担当: 作業ブランチ `plan/2026-10-26-flag-corner-color` に意味ごとに commit（country の型と関数 → fetchflags と生成物 → bot → docs）。push はしない
2. 采配役: push、`main` への PR を作成、CI 3 ジョブ（go・tinygo-test・build）の成功を確認。実装レビュー担当のレビューを経て合格を確認
3. 利用者: PR をマージ（main はルールセットで保護されており PR 経由のみ）
4. 采配役: マージ後に `npx wrangler deploy` で本番に出す
5. 利用者: 実機のダークモード・ライトモードで、フランス・日本・イギリスなどの返信とクイズを見て、cover の国旗の角の白い線が消えたこと、contain の国旗が従来どおりであることを確認。残る場合は未確定事項の「切り取りの仮定」「片側が白の国」を手がかりに再検討する
